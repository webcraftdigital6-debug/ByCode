# BlocklyCode

Браузерная платформа для обучения программированию через визуальные блоки (Google Blockly). Пользователь собирает программу из блоков, а приложение генерирует из них код на выбранном языке и выполняет его прямо в браузере.

## Возможности

- **4 языка исполнения без бэкенда**: JavaScript (нативно), Python (pyodide/WASM), Lua (fengari), PHP (php-wasm). Сгенерированный код отображается в редакторе Ace.
- **Код в панели понятен новичку**: блок «создать текст из» генерирует обычную склейку (`+` в JavaScript, `str()` в Python, `..` с `tostring()` в Lua, `.` в PHP), а не `join()`, `table.concat()` или списковые включения; если Blockly переименовал переменную из-за служебного слова языка (`name` → `name2`), над её объявлением в Ace появляется поясняющий комментарий (RU/EN).
- **Задачу можно решить и кодом, без блоков**: если поле блоков пустое, автопроверка оценивает вывод программы, набранной в редакторе Ace, и даёт столько же звёзд, сколько дало бы оптимальное решение блоками; блоки не затирают набранный код. Вывод обязан соответствовать условию задачи — «любая цифра на экране» не засчитывается, а верных решений может быть несколько (разные числа, порядок строк, RU/EN). Инвариант проверяет guard-тест `tests/code_solutions.test.ts` по всем 65 задачам.
- **65 обучающих задач** с автопроверкой, в трёх разделах («Основа» / «Найди ошибку» / «Продвинутый»):
  - 55 базовых: вывод → арифметика → переменные → математика (округление, ограничение, функции и константы) → условия → логика (и/или/не, проверка двух условий сразу, тернарный выбор) → циклы (первый цикл, повтор N раз, случайные числа, сумма, вложенные циклы, ввод пользователя, «повторять, пока» со счётчиком до предела и «повторять, пока не» с повторным запросом числа) → серия «Магический инвентарь» про списки (длина и чтение ячейки по индексу, замена элемента, добавление в конец, поиск позиции и удаление, случайная выдача предмета, разбор инвентаря до пустого списка) → обход и анализ списка (foreach, срез, фильтр, min/max, сортировка, среднее, медиана, сумма по позициям, поле 3×3 — список списков и двойной индекс, break) → функции (определение, параметры, возврат, функция-предикат с вызовом в условии «если») → строки (длина, символ по номеру, накопление строки в цикле, срез, регистр/обрезка, поиск, подсчёт, замена) → списки (split/join, переворот, повтор, позиция) → «Угадай число» → мини-игра «Охота за кладом» (цикл + список + случайность в одной программе) → проект «Магический инвентарь», который собирает все навыки раздела в одной программе;
  - 6 задач «Найди ошибку» (1–6) отдельным разделом: в пустую рабочую область автоматически подкладывается готовая сломанная программа — ученик должен найти и исправить баг (блоками или правкой кода в редакторе);
  - 4 продвинутые (A1–A4): анализ числа, сумма массива, min/max, частоты символов.
  - Каждая задача оценивается 1–3 звёздами за оптимальность решения, есть пошаговые подсказки (RU/EN); названия блоков и разделов в них подсвечиваются цветом категории Blockly.
- **Классы для учителей**: создание классов, добавление учеников по email, назначение задач, экран прогресса ученика (решено/звёзды/активность + таблица назначений с statuses). Ученики видят назначенные задания в разделе «Мои задания».
- **Уведомления учителю**: при выполнении назначенной задачи учеником в ленту падает «ученик выполнил задание» — красный бейдж непрочитанных на кнопке «⋯», панель «🔔 Уведомления» со списком и автоотметкой о прочтении (поллинг 60 с).
- **Монетизация (freemium)**: тариф Free — 1 класс, до 5 учеников, 3 назначения заданий в месяц; тариф Pro — 10 классов, до 200 учеников, без лимита назначений. Апгрейд промокодом (одноразовым, активирует Pro на 30 дней); плата картой подключается через env-переменные SMTP. Дашборд показывает расходование лимитов, при превышении — paywall.
- **Прогресс задач синхронизируется**: localStorage (гости, офлайн) ↔ сервер (авторизованные). Решение назначенной учителем задачи автоматически помечает назначение выполненным.
- **Обратная связь**: кнопка «✉️» в шапке — баг/пожелание/вопрос; доставляется на почту владельцу (Nodemailer SMTP) с фолбэком в `server/data/feedback.json`; rate-limit 5 сообщений/час.
- **Кастомные блоки**: вывод значения с цветом (`add_text`), ввод (`py_input`, `py_input_number`), словари (`dict_*` — категория «Словари» в тулбоксе), дата, слайдер, угол, битмап, HSV-цвет.
- **Аккаунты**: регистрация/вход по email+пароль (сессии в SQLite, пароли — scrypt), сохранение рабочих областей на сервере; при недоступности API — автоматический откат на localStorage.
- **Интерфейс**: полная локализация RU/EN, тёмная тема, мобильная версия, поиск по тулбоксу, аннотации поверх рабочей области (Konva), экспорт/импорт проектов (XML/JSON), генерация PDF.
- **Онбординг**: интерактивный spotlight-тур по интерфейсу при первом визите (10 шагов, RU/EN, автоматический пропуск невидимых на мобильных целей); повторный запуск — кнопка «🧭 Обучение» в меню «⋯» или в бургер-меню.

## Запуск

Требуется Node.js 18+ (22+ — для встроенного node:sqlite).

```bash
# 1. Установить зависимости (корень + app)
npm install

# 2. Запустить бэкенд (порт 4000) и фронт-девсервер (порт 8080) одновременно
npm run dev

# или по отдельности:
npm run server   # только API: http://127.0.0.1:4000
npm start        # только фронт: http://localhost:8080 (проксирует /api на 4000)
```

Продакшен-сборка:

```bash
npm run build    # собирает app/dist/
```

> **Важно (хостинг):** ввод через `input()` использует `SharedArrayBuffer`, поэтому страница должна отдаваться с заголовками **COOP: same-origin** и **COEP: require-corp** (crossOriginIsolated). Для Apache в `dist/` копируется готовый `.htaccess`; для Nginx/др. задайте заголовки в конфиге.

## Монетизация и админ-инструменты

- Тарифы: `store.PLANS` в `server/store.js` (Free: 1 класс / 5 учеников / 3 назначения в месяц; Pro: 10 / 200 / без лимита).
- Генерация промокодов:
  ```bash
  npm run promo -- SCH2026            # одноразовый код Pro, без срока годности кода
  npm run promo -- MARCH --days 30    # код истекает через 30 дней
  ```
  Учитель вводит код в «Классы → Подписка». Активация — Pro на 30 дней.
- Почта для обратной связи: `FEEDBACK_TO` (по умолчанию задана в `server/feedback.js`), SMTP — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`.
- Данные сервера (SQLite, JSON-фолбэки, журнал фидбэка) — в `server/data/` (в git не попадает).

## Деплой на Render (бесплатный URL без домена)

Проект готов к деплою одним сервисом: `npm run build` собирает фронтенд в `app/dist`, `npm run start` поднимает Express, который раздаёт статику, SPA-fallback и API (`render.yaml` уже в репозитории).

1. Залей репозиторий на GitHub (Render деплоит из Git).
2. [render.com](https://render.com) → **New → Web Service** → подключи репозиторий.
3. Render подхватит `render.yaml` (region: frankfurt, plan: free). Если выбираешь вручную:
   - **Build Command:** `npm install && npm run build`
   - **Start Command:** `npm run start`
   - Node 22 (в `engines`).
4. Environment-переменные (Dashboard → Environment):
   - `FEEDBACK_TO` — куда приходит обратная связь (по умолчанию уже задана).
   - `SMTP_HOST/PORT/USER/PASS/FROM` — реальная отправка писем; без них фидбэк пишется в файл.
5. Через пару минут получишь `https://<имя-сервиса>.onrender.com`.

**Ограничения бесплатного тарифа:**
- **Файловая система ephemeral**: при каждом деплое/перезапуске SQLite в `server/data/` обнуляется (аккаунты и классы пропадают). Для постоянных данных подключи **Persistent Disk** (Render → Disks, точка монтирования например `/data`) и задай `DATA_DIR=/data` — на диске данные выживают.
- Сервис засыпает через 15 минут без трафика, первый запрос после сна медленный (~30 сек).
- 750 часов/месяц бесплатно — для одного сервиса хватает с запасом.

## Тесты и качество кода

```bash
npm test           # все тесты (vitest, из app/)
npm run lint       # ESLint (0 ошибок обязателен, предупреждения допустимы)
npm run typecheck  # tsc --noEmit
cd app && npm run format   # Prettier (переписать файлы)
```

CI (`.github/workflows/ci.yml`) на каждый push/PR в main гоняет: install → typecheck → lint → tests → build.

Тесты проверяют валидаторы задач: общий раннер `tests/all_tasks.test.ts` прогоняет все 65 задач (валидатор обязан принимать корректный вывод — защита от регрессий вида «задача непроходима») и следит за целостностью реестра: каждая задача стоит в порядке прохождения, а номер в её заголовке («Задача N») равен позиции в этом порядке, `tests/solutions.test.ts` — эталонные решения из `solutions/*.xml` (XML → генерация JS → исполнение → валидация), `tests/fixbugs.test.ts` — инвариант задач «Найди ошибку»: сломанный starter обязан НЕ проходить, исправленное решение — проходить на 3 звезды. Отдельные e2e-решения со звёздами есть для mult_table, first_even_break, first_function и char_freq. `tests/dice_chatterbox.test.ts` — валидаторы задач с рандомом и вводом (dice_rolls, chatterbox): форма вывода важнее значений, негативные сценарии вне диапазона/без цикла/без блоков ввода. `tests/notifications.test.ts` — лента уведомлений учителя (тексты RU/EN, бейдж, отметка о прочтении, поллинг). `tests/glossary.test.ts` — справочник тем (содержимое на 4 языках, каждая тема привязана к задаче через `infoTopics`, показ/скрытие при переходе). `tests/str_tasks.test.ts` — строковые задачи (str_length, str_charat, str_substring, str_clean, str_echo): эталонный XML прогоняется до 3 звёзд, вывод «только текстовыми блоками» не засчитывается. `tests/extended_blocks.test.ts` — то же для задач на «умные» блоки (поиск/подсчёт/замена в строке, логика, математика, чтение и правка списков); задачи со случайным выводом проверяются только в solutions.test.ts. `tests/while_grid_predicate.test.ts` — задачи на цикл «пока / пока не», пустой список как условие, поле 3×3, функцию-предикат и «Охоту за кладом» (3★ на эталоне, обман печатью и пустой вывод). `tests/code_solutions.test.ts` — режим «решение кодом в Ace»: по каждой из 65 задач пустое поле блоков + корректный вывод обязано засчитываться и давать верхнюю шкалу звёзд, а посторонний вывод — не засчитываться (корректный вывод получается из `solutions/*.xml`: XML → генерация JS → исполнение). API-сервер покрывается интеграционными тестами `npm run test:server` (supertest, временная DATA_DIR).

## Добавление новой задачи

1. Добавьте id в тип `TaskId` в `app/src/tasks/types.ts`.
2. Опишите задачу: `title`, `description`, `hint` (RU/EN) и функцию `validate(ws, outputLines, lang)` → `{ ok, stars }`. Если задача вводит новый термин, укажите `infoTopics` — под условием появится справочная секция с примерами на четырёх языках (темы в `app/src/ui/glossary.ts`, при необходимости добавьте новую).
3. Внесите id в `TASKS_ORDER_BY_DIFFICULTY` (basic/fixbugs/advanced). Номер в заголовке («Задача N: …», RU и EN) обязан совпадать с позицией в этом списке — его проверяет `tests/all_tasks.test.ts`, поэтому вставка или перестановка задачи требует перенумерации заголовков всего уровня.
4. Добавьте тест валидатора в `app/tests/` и (опционально) эталонное решение в `solutions/`.

## Справочник тем (`app/src/ui/glossary.ts`)

Под условием задачи показывается справочная секция с объяснением новых терминов и примерами кода на JavaScript, Python, Lua и PHP. Тема привязывается к задаче через поле `infoTopics` (`TaskDef`) и рендерится в `#glossaryInfoSection` при переключении задачи. Это дополняет старые захардкоженные `#…InfoSection` в `index.html`; новые темы добавляются в `TOPIC_CONTENT` как данные, а не разметка. Идентификаторы тем перечислены в `GLOSSARY_TOPICS` (выводятся из `TOPIC_CONTENT`, поэтому не разъезжаются): `functions`, `nested_loops`, `break_continue`, `sorting`, `repeat_n_times`, `random_numbers`, `user_input`, `string_concat`, `string_length`, `string_indexing`, `string_slice`, `string_case_trim`, `string_search`, `string_replace`, `boolean_logic`, `ternary_null`, `math_functions`, `rounding`, `split_join`, `list_operations`, `list_indexing`, `list_add_remove`, `list_random_choice`, `string_accumulate`, `while_until`, `list_is_empty`, `nested_lists`, `predicate_functions`, `dict`.

## Статус и ограничения

- Авторизация — email+пароль (scrypt-хэши, сессии в SQLite). OAuth (Google/Yandex/GitHub) — заглушки, ждут ключи.
- Оплата картой для Pro не подключена: активация через промокоды (`npm run promo`), интеграция платёжного провайдера — следующий этап.
- Для отправки фидбэка письмом задайте SMTP-переменные окружения; без них сообщения копятся в `server/data/feedback.json`.
