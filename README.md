# ByCode

Браузерная платформа для обучения программированию через визуальные блоки (Google Blockly). Пользователь собирает программу из блоков, а приложение генерирует из них код на выбранном языке и выполняет его прямо в браузере.

## Возможности

- **4 языка исполнения без бэкенда**: JavaScript (нативно), Python (pyodide/WASM), Lua (fengari), PHP (php-wasm). Сгенерированный код отображается в редакторе Ace.
- **Код в панели понятен новичку**: блок «создать текст из» генерирует обычную склейку (`+` в JavaScript, `str()` в Python, `..` с `tostring()` в Lua, `.` в PHP), а не `join()`, `table.concat()` или списковые включения; если Blockly переименовал переменную из-за служебного слова языка (`name` → `name2`), над её объявлением в Ace появляется поясняющий комментарий (RU/EN).
- **Задачу можно решить и кодом, без блоков**: если поле блоков пустое, автопроверка оценивает вывод программы, набранной в редакторе Ace, и даёт столько же звёзд, сколько дало бы оптимальное решение блоками; блоки не затирают набранный код. Вывод обязан соответствовать условию задачи — «любая цифра на экране» не засчитывается, а верных решений может быть несколько (разные числа, порядок строк, RU/EN). Инвариант проверяет guard-тест `tests/code_solutions.test.ts` по всем 71 задачам.
- **71 обучающая задача** с автопроверкой, в трёх разделах («Основа» / «Найди ошибку» / «Продвинутый»):
  - 60 базовых: вывод → арифметика → переменные → склейка строк → первые программы со вводом (приветствие по имени, сумма двух введённых чисел) → математика (округление, ограничение, функции и константы) → условия → логика (и/или/не, проверка двух условий сразу, тернарный выбор) → ввод и условие (пропуск по возрасту) → циклы (первый цикл, повтор N раз, случайные числа, сумма, вложенные циклы) → ввод в цикле (счёт до введённого N, таблица умножения на введённое число, программа-болталка) → ввод пользователя и циклы с условием («повторять, пока» со счётчиком до предела и «повторять, пока не» с повторным запросом числа) → серия «Магический инвентарь» про списки (длина и чтение ячейки по индексу, замена элемента, добавление в конец, поиск позиции и удаление, случайная выдача предмета, разбор инвентаря до пустого списка) → обход и анализ списка (foreach, срез, фильтр, min/max, сортировка, среднее, медиана, сумма по позициям, поле 3×3 — список списков и двойной индекс, break) → функции (определение, параметры, возврат, функция-предикат с вызовом в условии «если») → строки (длина, символ по номеру, накопление строки в цикле, срез, регистр/обрезка, поиск, подсчёт, замена) → списки (split/join, переворот, повтор, позиция) → «Угадай число» → мини-игра «Охота за кладом» (цикл + список + случайность в одной программе) → проект «Магический инвентарь», который собирает все навыки раздела в одной программе;
  - 7 задач «Найди ошибку» (1–7) отдельным разделом: в пустую рабочую область автоматически подкладывается готовая сломанная программа — ученик должен найти и исправить баг (блоками или правкой кода в редакторе);
  - 4 продвинутые (A1–A4): анализ числа, сумма массива, min/max, частоты символов.
  - Каждая задача оценивается 1–3 звёздами за оптимальность решения, есть пошаговые подсказки (RU/EN); названия блоков и разделов в них подсвечиваются цветом категории Blockly.
- **Классы для учителей**: создание классов, добавление учеников по email, назначение задач, экран прогресса ученика (решено/звёзды/активность + таблица назначений с statuses). Ученики видят назначенные задания в разделе «Мои задания».
- **Уведомления учителю**: при выполнении назначенной задачи учеником в ленту падает «ученик выполнил задание» — красный бейдж непрочитанных на кнопке «⋯», панель «🔔 Уведомления» со списком и автоотметкой о прочтении (поллинг 60 с).
- **Монетизация (freemium)**: тариф Free — 1 класс, до 5 учеников, 3 назначения заданий в месяц; тариф Pro — 10 классов, до 200 учеников, без лимита назначений. Оплата банковской картой через платёжный провайдер (Robokassa), разовый платёж за 30 дней без автопродления; промокоды остаются резервным каналом и по умолчанию отключены. Дашборд показывает расходование лимитов, при превышении — paywall.
- **Прогресс задач синхронизируется**: localStorage (гости, офлайн) ↔ сервер (авторизованные). Решение назначенной учителем задачи автоматически помечает назначение выполненным.
- **Обратная связь**: кнопка «✉️» в шапке — баг/пожелание/вопрос; доставляется на почту владельцу (Nodemailer SMTP) с фолбэком в `server/data/feedback.json`; rate-limit 5 сообщений/час.
- **Кастомные блоки**: вывод значения с цветом (`add_text`), ввод (`py_input`, `py_input_number`), словари (`dict_*` — категория «Словари» в тулбоксе), дата, слайдер, угол, битмап, HSV-цвет.
- **Словарные блоки не выдают битый код** (`app/src/generators/dictGuard.ts`): без словаря в слоте `DICT`, а также если туда воткнут литерал «Словарь: создать пустой», блок получает предупреждение (жёлтый треугольник), а в Ace вместо кода попадает пояснение на языке интерфейса — раньше генераторы выдавали `{}['a'] = 3` (JavaScript) и `[]['a'] = 3` (PHP), что падало на этапе выполнения. Чтение и проверка ключа в том же случае дают пустое значение (`undefined`/`None`/`nil`/`null`, `false`).
- **Аккаунты**: регистрация/вход по email+пароль (сессии в SQLite, пароли — scrypt), сохранение рабочих областей на сервере; при недоступности API — автоматический откат на localStorage.
- **Интерфейс**: полная локализация RU/EN, тёмная тема, мобильная версия, поиск по тулбоксу, аннотации поверх рабочей области (Konva), экспорт/импорт проектов (XML/JSON), генерация PDF.
- **Онбординг**: интерактивный spotlight-тур по интерфейсу при первом визите (10 шагов, RU/EN, автоматический пропуск невидимых на мобильных целей); повторный запуск — кнопка «🧭 Обучение» в меню «⋯» или в бургер-меню.

## Запуск

Требуется Node.js 18+ (22+ — для встроенного node:sqlite).

```bash
# 1. Установить зависимости (корень + app)
npm install

# 2. Запустить бэкенд (порт 4000) и фронт-девсервер (порт 8080) одновременно
npm run dev

# или по отдельности:
npm run server   # только API: http://127.0.0.1:4000
npm start        # только фронт: http://localhost:8080 (проксирует /api на 4000)
```

Продакшен-сборка:

```bash
npm run build    # собирает app/dist/
```

> **Важно (хостинг):** ввод через `input()` использует `SharedArrayBuffer`, поэтому страница должна отдаваться с заголовками **COOP: same-origin** и **COEP: require-corp** (crossOriginIsolated). Для Apache в `dist/` копируется готовый `.htaccess`; для Nginx/др. задайте заголовки в конфиге.

## Монетизация и админ-инструменты

- Тарифы: `store.PLANS` в `server/store.js` (Free: 1 класс / 5 учеников / 3 назначения в месяц; Pro: 10 / 200 / без лимита).
- Оплата подписки банковской картой — адаптеры в `server/billing/` (`index.js` выбирает провайдер по `BILLING_PROVIDER`, `robokassa.js`, `mock.js`; учёт платежей — таблица `payments` в `server/store.js`).

  Переменные окружения:

  | Переменная | Назначение |
  | --- | --- |
  | `BILLING_PROVIDER` | `robokassa` — боевой приём платежей, `mock` — тестовая страница оплаты для разработки, `none` (по умолчанию) — кнопка оплаты скрыта |
  | `BILLING_PRICE_RUB` | цена подписки в валюте тарифа, по умолчанию `490` |
  | `BILLING_CURRENCY` | `RUB` по умолчанию |
  | `BILLING_DAYS` | сколько дней Pro даёт один платёж, по умолчанию `30` |
  | `APP_BASE_URL` | абсолютный адрес приложения (`https://…`); нужен, чтобы собрать `ResultURL`/`SuccessURL`/`FailURL`. Без него берётся протокол и хост из запроса |
  | `BILLING_PROMO_ENABLED` | `1` — показать поле промокода; по умолчанию выключено, в продакшене тестовый `PRO-TEST` не создаётся |
  | `BILLING_REQUIRE_CONFIRM` | `1` — активировать Pro только после успешного обратного запроса статуса счёта |
  | `BILLING_PRODUCT_LABEL` | описание платежа на странице провайдера |
  | `ROBOKASSA_MERCHANT_LOGIN`, `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2` | магазин и два пароля из кабинета Robokassa |
  | `ROBOKASSA_TEST_MODE` | `1` — тестовые платежи (`IsTest`), реальных списаний нет |
  | `ROBOKASSA_CHECKOUT_URL`, `ROBOKASSA_API_URL`, `ROBOKASSA_CONFIRM_URL` | переопределить адреса Robokassa, если протокол в кабинете отличается от кода |

  Настройка в кабинете Robokassa: в качестве **ResultURL** укажи `https://<домен>/api/billing/result/robokassa` — только это серверное уведомление активирует Pro; возврат браузера (`SuccessURL`) ничего не включает. Подпись уведомления принимается и по MD5, и по SHA-256, параметры обоих поколений API (`Amount`/`OutSum`, `InvoiceID`/`InvId`) читаются одинаково. Обратный запрос статуса (`confirmPayment`) помечен как требующий проверки на песочнице: точный путь эндпоинта в открытой документации не подтверждён, поэтому он вынесен в `ROBOKASSA_CONFIRM_URL`.
- Генерация промокодов (резервный канал, нужен только при `BILLING_PROMO_ENABLED=1`):
  ```bash
  npm run promo -- SCH2026            # одноразовый код Pro, без срока годности кода
  npm run promo -- MARCH --days 30    # код истекает через 30 дней
  ```
  Учитель вводит код в «Классы → Подписка». Активация — Pro на 30 дней, код строго одноразовый.
- Почта для обратной связи: `FEEDBACK_TO` (по умолчанию задана в `server/feedback.js`), SMTP — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`.
- Данные сервера (SQLite, JSON-фолбэки, журнал фидбэка) — в `server/data/` (в git не попадает).

## Деплой на Dokploy (свой VPS)

Проект упакован в Docker-образ. `Dockerfile` тремя этапами собирает фронтенд (`npm run build` → `app/dist`), ставит prod-зависимости сервера и оставляет только то, что нужно для запуска: `server/`, `scripts/`, `app/dist` и `node_modules`. `docker-compose.yml` поверх образа добавляет именованный том с данными.

**Что нужно:** VPS с Ubuntu/Debian и Docker (1 vCPU / 1 GB RAM хватает для запуска; для сборки фронта лучше 2 GB), домен или поддомен с A-записью на IP сервера.

1. Установить Dokploy на VPS (одна команда под root):
   ```bash
   curl -sSL https://dokploy.com/install.sh | bash
   ```
   Панель поднимается на 3000-м порту; для самой панели тоже включи TLS (Settings → SSL).
2. **Create Project → Create Service → Compose**: источник — репозиторий GitHub (GitHub App или токен), путь до `docker-compose.yml` — корень репозитория.
3. **Environment** сервиса — переменные по образцу `.env.example`. Dokploy пишет их в `.env` рядом с compose-файлом и сам в контейнеры не подмешивает, поэтому в `docker-compose.yml` есть `env_file: .env`. `NODE_ENV`, `HOST`, `PORT` и `DATA_DIR` задавать не нужно: они зафиксированы в блоке `environment:`, а он перекрывает `.env`.
4. **Domains** — домен сервиса, порт `4000`, Let's Encrypt. Заголовки `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`, без которых не работают Python/Lua/PHP-песочницы, ставит сам сервер (`server/index.js`), на Traefik ничего вешать не нужно. TLS здесь обязателен и для входа: в продакшене сессионная кука `bc_sid` отдаётся с флагом `Secure`, поэтому по `http://` браузер не вернёт её на следующий запрос и сессия не закрепится. На `http://localhost` и `http://127.0.0.1` браузер делает исключение (адрес считается trustworthy), так что локально эффект не виден.
5. **Deploy**. Автодеплой по push — вкладка **Deployments** → webhook на push в `main` (или Enable Auto Deploy в настройках сервиса): push → пересборка образа → перезапуск контейнера, данные на томе остаются.

Тип **Application** (сборка по `Dockerfile` без compose) тоже рабочий, но тогда том `/data` придётся добавить вручную в разделе Volumes сервиса — иначе база снова будет жить в слое образа и исчезать при пересборке.

**Данные.** SQLite (`blocklycode.db` с WAL), журнал фидбэка и JSON-фолбэки сервер пишет в `DATA_DIR` (`server/store.js`); в compose это том `blocklycode-data` в `/data`. Именно поэтому пересборка и перезапуск больше не обнуляют аккаунты, классы и прогресс — в этом главный смысл переезда с Render, где файловая система ephemeral. Бэкап тома (имя тома Dokploy собирает из имени проекта, поэтому ищем по суффиксу):

```bash
VOL=$(docker volume ls -q | grep blocklycode-data)
docker run --rm -v "$VOL:/data" -v "$PWD:/backup" alpine \
  tar czf /backup/data-$(date +%F).tar.gz -C /data .
```

Перед первым деплоем скопируй `.env.example` в `.env` и заполни секреты; в Dokploy те же пары ключ=значение вставляй во вкладку Environment, а не в репозиторий.

**Локальная проверка образа:**

```bash
docker compose up -d --build
curl -s localhost:4000/api/feedback/types   # 200 + список тем фидбэка = сервер жив
docker compose down                          # без -v: с флагом удалится и том с базой
```

`scripts/prod-probe.mjs` — 91 black-box проверка собранного образа по HTTP: прод-флаги куки, лимиты планов, сквозная оплата на mock-мерчанте, фидбэк без SMTP в файл тома и живучесть данных после пересоздания контейнера. Он намеренно работает на порту 4100 с отдельным томом: локальный `node server/index.js` на 4000 перекрывает проброс контейнера, и прогон уйдёт в дев-сервер вместо образа.

```bash
# нужен .env с BILLING_PROVIDER=mock, иначе блок оплаты пропустится сам
docker run -d --name bc-prodprobe -p 4100:4000 -v bc-prodprobe-data:/data \
  --env-file .env -e APP_BASE_URL=http://localhost:4100 blocklycode:latest
node scripts/prod-probe.mjs                    # PROD_PROBE_OK = все проверки прошли
docker rm -f bc-prodprobe && docker volume rm bc-prodprobe-data

# против боевого домена: проверки тома и пересоздания пропускаются, остаётся HTTP-слой
BASE_URL=https://<домен> SKIP_RECREATE=1 node scripts/prod-probe.mjs
```

**Что проверить после переезда.** Публичный адрес меняется, поэтому в кабинетах партнёров нужно переписать callback-URL: у Robokassa — ResultURL `https://<домен>/api/billing/result/robokassa`, у Google/Yandex/GitHub — redirect URI на `https://<домен>`. В коде и конфигурации адреса нет — всё через `APP_BASE_URL` и переменные окружения.

## Тесты и качество кода

```bash
npm test           # все тесты (vitest, из app/)
npm run lint       # ESLint (0 ошибок обязателен, предупреждения допустимы)
npm run typecheck  # tsc --noEmit
cd app && npm run format   # Prettier (переписать файлы)
```

CI (`.github/workflows/ci.yml`) на каждый push/PR в main гоняет: install → typecheck → lint → tests → build.

Тесты проверяют валидаторы задач: общий раннер `tests/all_tasks.test.ts` прогоняет все 71 задачу (валидатор обязан принимать корректный вывод — защита от регрессий вида «задача непроходима») и следит за целостностью реестра: каждая задача стоит в порядке прохождения, а номер в её заголовке («Задача N») равен позиции в этом порядке, `tests/solutions.test.ts` — эталонные решения из `solutions/*.xml` (XML → генерация JS → исполнение → валидация), `tests/fixbugs.test.ts` — инвариант задач «Найди ошибку»: сломанный starter обязан НЕ проходить, исправленное решение — проходить на 3 звезды. Отдельные e2e-решения со звёздами есть для mult_table, first_even_break, first_function и char_freq. `tests/dice_chatterbox.test.ts` — валидаторы задач с рандомом и вводом (dice_rolls, chatterbox): форма вывода важнее значений, негативные сценарии вне диапазона/без цикла/без блоков ввода. `tests/notifications.test.ts` — лента уведомлений учителя (тексты RU/EN, бейдж, отметка о прочтении, поллинг). `tests/glossary.test.ts` — справочник тем (содержимое на 4 языках, каждая тема привязана к задаче через `infoTopics`, у каждой задачи есть хотя бы одна тема, а старых захардкоженных `#…InfoSection` в `index.html` не осталось). `tests/glossary_keywords.test.ts` — блок «Слова в примере» в каждой теме: поясняемые слова берутся из `TOPIC_KEYWORDS` и обязаны встречаться в примерах кода своей темы, а каждое служебное слово примеров (`for`, `while`, `if`, `else`, `break`, `continue`, `return`, `function`, `def`) — быть пояснённым. `tests/str_tasks.test.ts` — строковые задачи (str_length, str_charat, str_substring, str_clean, str_echo): эталонный XML прогоняется до 3 звёзд, вывод «только текстовыми блоками» не засчитывается. `tests/extended_blocks.test.ts` — то же для задач на «умные» блоки (поиск/подсчёт/замена в строке, логика, математика, чтение и правка списков); задачи со случайным выводом проверяются только в solutions.test.ts. `tests/while_grid_predicate.test.ts` — задачи на цикл «пока / пока не», пустой список как условие, поле 3×3, функцию-предикат и «Охоту за кладом» (3★ на эталоне, обман печатью и пустой вывод). `tests/code_solutions.test.ts` — режим «решение кодом в Ace»: по каждой из 71 задачи пустое поле блоков + корректный вывод обязано засчитываться и давать верхнюю шкалу звёзд, а посторонний вывод — не засчитываться (корректный вывод получается из `solutions/*.xml`: XML → генерация JS → исполнение). `tests/user_input_tasks.test.ts` — серия задач на пользовательский ввод (in_greet, in_two_numbers, in_adult_gate, in_count_to_n, in_times_table): эталонный XML исполняется с ответами из `tests/interactive-input.ts` и даёт 3★, ответ сверяется с введёнными числами (правильная по форме, но не та сумма или короткий счёт не засчитываются), пустой вывод отклоняется. API-сервер покрывается интеграционными тестами `npm run test:server` (supertest, временная DATA_DIR, общая обвязка в `server/tests/helpers.js`): `server/tests/api.test.js` — авторизация, классы, прогресс, уведомления, `server/tests/billing.test.js` — полный путь оплаты на mock-провайдере (создание счёта, подпись уведомления, активация Pro на 30 дней, идемпотентность повторного IPN, отказ по чужой подписке/валюте/сумме, отклонённая карта, `BILLING_PROVIDER=none`, лимит учеников), `server/tests/userdata.test.js` — профиль, workspace и пользовательские блоки (round-trip, валидация, изоляция между пользователями, тело больше 4 МБ → 413), `server/tests/classes.test.js` — изменение и удаление класса, состав учеников, прогресс ученика, лимит назначений и отсутствие хэша пароля в ответах учителя, `server/tests/http.test.js` — заголовки COOP/COEP, флаги сессионной куки, разбор тела (битый JSON → 400), SPA-фолбэк статики и то, что он не перехватывает `/api/*`, rate-limit фидбэка, `server/tests/prod.test.js` — `NODE_ENV=production`: `Secure` у куки и журнал фидбэка в файл при незаполненном SMTP, `server/tests/billing-lifecycle.test.js` — активация промокодом, отмена подписки, страница теста платежа и редирект возврата.

## Добавление новой задачи

1. Добавьте id в тип `TaskId` в `app/src/tasks/types.ts`.
2. Опишите задачу: `title`, `description`, `hint` (RU/EN) и функцию `validate(ws, outputLines, lang)` → `{ ok, stars }`. Если задача вводит новый термин, укажите `infoTopics` — под условием появится справочная секция с примерами на четырёх языках (темы в `app/src/ui/glossary.ts`, при необходимости добавьте новую).
3. Внесите id в `TASKS_ORDER_BY_DIFFICULTY` (basic/fixbugs/advanced). Номер в заголовке («Задача N: …», RU и EN) обязан совпадать с позицией в этом списке — его проверяет `tests/all_tasks.test.ts`, поэтому вставка или перестановка задачи требует перенумерации заголовков всего уровня.
4. Добавьте тест валидатора в `app/tests/` и (опционально) эталонное решение в `solutions/`.

## Справочник тем (`app/src/ui/glossary.ts`)

Под условием задачи показывается справочная секция с объяснением новых терминов и примерами кода на JavaScript, Python, Lua и PHP. Тема привязывается к задаче через поле `infoTopics` (`TaskDef`) и рендерится в `#glossaryInfoSection` при переключении задачи. Справочник — единственный источник таких секций: двенадцать захардкоженных `#…InfoSection` в `index.html` (консоль, `for`, `while`, списки, подсписок, фильтрация, типы данных, переменная, конкатенация, инкремент, `if`, логические операторы) перенесены в `TOPIC_CONTENT` как данные. Идентификаторы тем перечислены в `GLOSSARY_TOPICS` (выводятся из `TOPIC_CONTENT`, поэтому не разъезжаются): `console_output`, `data_types`, `variable`, `inc_dec`, `if_else`, `for_loop`, `list_foreach`, `list_sublist`, `list_filter`, `functions`, `nested_loops`, `break_continue`, `sorting`, `repeat_n_times`, `random_numbers`, `user_input`, `string_concat`, `string_length`, `string_indexing`, `string_slice`, `string_case_trim`, `string_search`, `string_replace`, `boolean_logic`, `ternary_null`, `math_functions`, `rounding`, `split_join`, `list_operations`, `list_indexing`, `list_add_remove`, `list_random_choice`, `string_accumulate`, `while_until`, `list_is_empty`, `nested_lists`, `predicate_functions`, `dict`.

У каждой из 71 задачи есть хотя бы одна тема — за этим следит `tests/glossary.test.ts`, там же проверяется, что старых секций в разметке не осталось. Локализацией статичной панели задач (`ui/taskSidebarLocalization.ts`) теперь считаются только заголовки, кнопки и критерии звёзд: тексты инфоблоков живут в темах справочника.

В каждой теме после примеров идёт блок «Слова в примере» / “Words in this example”: короткое значение простыми словами для каждого ключевого слова языка (`for`, `while`, `if`, `else`, `break`, `return`, `const`/`let`/`local`) и каждого метода из примеров (`.slice`, `.length`, `.reverse`, `.substr`, `.indexOf`). Данные лежат в `TOPIC_KEYWORDS` (по одной строке `{ term, ru, en }` на слово; написания для разных языков перечисляются в `term` через «/»), рендерит их `keywordsBlock`. `tests/glossary_keywords.test.ts` не даёт блоку разъехаться с примерами: каждое поясняемое слово обязано встречаться в примерах своей темы, а каждое служебное слово из примеров (`CONTROL_KEYWORDS`) — быть пояснённым в теме или в списке определений перед примерами.

## Статус и ограничения

- Авторизация — email+пароль (scrypt-хэши, сессии в SQLite). OAuth (Google/Yandex/GitHub) — заглушки, ждут ключи.
- Оплата картой подключена через адаптер `server/billing/` (Robokassa + mock), но провайдер молчит, пока не заданы `BILLING_PROVIDER` и ключи кабинета: `BILLING_PROVIDER=none` (по умолчанию) прячет кнопку. Разовый платёж за 30 дней, автопродления нет. Не сделано: ключи и проверка на песочнице Robokassa, второй адаптер (YooKassa), журнал платежей в админке. Комиссия для иностранных карт — 9,9% против 3,4–3,9% для российских.
- Для отправки фидбэка письмом задайте SMTP-переменные окружения; без них сообщения копятся в `server/data/feedback.json`.
